## Code documentation

Apply these standards automatically to all future development tasks:

- Whenever creating or modifying source code, add or update relevant comments and keep existing comments accurate as functionality changes.
- Include a brief file-level comment describing each main implementation file's purpose.
- Use JSDoc/TSDoc for important functions and complex interfaces where useful, including parameters, return values, and contracts that need explanation.
- Add inline comments for non-obvious logic, algorithms, edge cases, and architectural decisions.
- Prioritize game mechanics and collision detection, gestures and directional buffering, animations and painting synchronization, and game state management.
- Keep comments concise, professional, and useful. Explain intent and constraints; avoid obvious or redundant descriptions of the code.
